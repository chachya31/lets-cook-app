# Requirements Document

## Introduction

本アプリケーションは、一人暮らしまたは2〜4人家族の世帯を対象とした自炊支援・食費節約Webアプリケーションです。Uber Eatsなどのデリバリーサービス依存からの脱却を支援し、簡単なレシピ提供により料理への心理的ハードルを下げ、食材の賞味期限や保管方法を提示することで計画的な買い物を促進し、食品ロスを削減します。

主要機能として、レシピ検索・編集、スケジュール管理（実績記録）、買い物リスト、アラート表示を提供します。バックエンドはJava (Spring Boot)とClean Architecture、フロントエンドはTypeScript (React, React Router, Redux)、インフラはAWSサーバーレス構成を採用します。

## Glossary

- **CookingApp**: 自炊支援・食費節約アプリケーションシステム全体
- **User**: アプリケーションを利用する登録ユーザー
- **Recipe**: 料理のタイトル、食材、手順、画像を含むレシピ情報
- **Schedule**: ユーザーの料理予定または実績の記録
- **PLANNED**: スケジュールの種別で、料理予定を示す
- **COOKED**: スケジュールの種別で、料理実績を示す
- **ShoppingList**: ユーザーの買い物リスト
- **Review**: レシピに対する星評価とコメント
- **AIAdvisor**: 食材に対する保存法や代替食材を提示するAI機能
- **Alert**: 料理実績がない期間が続いた際の警告表示
- **Administrator**: システム管理者
- **Cognito**: AWS Cognitoによる認証サービス
- **S3**: Amazon S3ストレージサービス
- **DynamoDB**: Amazon DynamoDBデータベースサービス

## Requirements

### Requirement 1: ユーザー登録と認証

**User Story:** ユーザーとして、アカウントを作成してログインし、自分のプロフィールを管理したい。そうすることで、個人に合わせた料理記録や買い物リストを保存できる。

#### Acceptance Criteria

1. ユーザーが有効なメールアドレスとパスワード要件を満たすパスワードを提供したとき、CookingAppはCognitoを使用して新しいアカウントを作成する
2. ユーザーが有効な認証情報を提供したとき、CookingAppはユーザーを認証し、システムへのアクセスを許可する
3. アクセストークンが1時間後、またはリフレッシュトークンが90日後に期限切れになったとき、CookingAppは再認証を要求する
4. ユーザーがプロフィール画像をアップロードしたとき、CookingAppはファイルサイズが5MB以下でフォーマットがJPEGまたはPNGであることを検証する
5. ユーザーがアカウント削除を要求したとき、CookingAppはアカウントとプロフィール画像を即座に削除し、投稿したレシピとレビューを匿名化する

### Requirement 2: レシピ検索と閲覧

**User Story:** ユーザーとして、カテゴリ、食材、調理時間でレシピを検索し、詳細を閲覧したい。そうすることで、自分に合った料理を見つけられる。

#### Acceptance Criteria

1. ユーザーがカテゴリ、食材、または調理時間を含む検索条件を指定したとき、CookingAppは一致するレシピを返す
2. ユーザーがレシピを選択したとき、CookingAppはレシピのタイトル、数量と単位を含む食材、調理手順、画像を表示する
3. ユーザーがレシピ詳細を閲覧したとき、CookingAppは表示可能ステータスのすべてのレビューを表示する
4. ユーザーが削除されたレシピを閲覧したとき、CookingAppはレシピが削除されたことを示すメッセージを表示する
5. レシピに食材が存在する場合、CookingAppは各食材を名前、数量、単位、任意のメモ、任意フラグとともに表示する

### Requirement 3: レシピ登録と編集

**User Story:** ユーザーとして、自分のレシピを登録・編集したい。そうすることで、オリジナルレシピを共有し、後で参照できる。

#### Acceptance Criteria

1. ユーザーがレシピのタイトル、食材、手順、任意の画像を提供したとき、CookingAppは新しいレシピを作成する
2. ユーザーが食材情報を提供したとき、CookingAppは名前が1〜50文字、数量が0〜9999の範囲、単位が事前定義リストからであることを検証する
3. ユーザーが自分のレシピを編集したとき、CookingAppはレシピ情報を更新する
4. ユーザーが自分のレシピを削除したとき、CookingAppはスケジュールと買い物リストの参照を保持しながらレシピを削除済みとしてマークする
5. ユーザーがレシピ画像をアップロードしたとき、CookingAppは画像をS3に保存し、ファイルサイズが5MB以下でフォーマットがJPEGまたはPNGであることを検証する

### Requirement 4: AIアドバイザー機能

**User Story:** ユーザーとして、選択した食材に対する保存法や代替食材の提案を受けたい。そうすることで、食材を無駄なく活用できる。

#### Acceptance Criteria

1. ユーザーが食材を選択してAIアドバイスを要求したとき、CookingAppはGemini APIを呼び出し、保存方法と代替食材を返す
2. AI APIの呼び出しが失敗し、24時間以内のキャッシュが存在するとき、CookingAppはキャッシュされた応答を表示する
3. AI APIの呼び出しが失敗し、キャッシュが存在しないとき、CookingAppは再試行ボタンと静的ヒントを表示する
4. AI APIのレート制限に達したとき、CookingAppはバナーメッセージを表示し、30秒後に自動的に再試行する
5. AI APIのレート制限に達したとき、CookingAppは手動再試行ボタンを提供する

### Requirement 5: レシピ評価機能

**User Story:** ユーザーとして、レシピに星評価とコメントを投稿し、他のユーザーの評価を閲覧したい。そうすることで、レシピの品質を判断できる。

#### Acceptance Criteria

1. ユーザーが1〜5の星評価と最大300文字の任意のコメントを提供したとき、CookingAppはレシピのレビューを作成する
2. ユーザーが自分のレビューを閲覧したとき、CookingAppは編集と削除を許可する
3. ユーザーがレビューを通報したとき、CookingAppは通報カウントを増加させる
4. レビューが3件以上の通報を受けたとき、CookingAppは自動的にステータスを非表示に設定する
5. ユーザーがレビューを閲覧したとき、CookingAppは表示可能ステータスのレビューのみを表示する

### Requirement 6: スケジュール管理機能

**User Story:** ユーザーとして、料理の予定と実績をカレンダーで管理したい。そうすることで、料理習慣を可視化し、継続できる。

#### Acceptance Criteria

1. ユーザーがカレンダーを閲覧したとき、CookingAppは選択された月または週の予定と実績のエントリを表示する
2. ユーザーが日付に対して料理活動を登録したとき、CookingAppはCOOKEDスケジュールエントリを作成し、LastCookingDateを更新する
3. ユーザーが将来の日付に対して料理予定を登録したとき、CookingAppはPLANNEDスケジュールエントリを作成する
4. ユーザーがPLANNEDエントリをCOOKEDに変換したとき、CookingAppはスケジュールタイプをCOOKEDに更新する
5. ユーザーが過去のスケジュールエントリの編集または削除を要求したとき、CookingAppは変更を許可する

### Requirement 7: サボり防止アラート機能

**User Story:** ユーザーとして、料理をしていない期間が続いたら警告を受けたい。そうすることで、自炊習慣を維持できる。

#### Acceptance Criteria

1. ユーザーがダッシュボードにアクセスし、LastCookingDateから3日が経過して4日目の0時になったとき、CookingAppはアラートモーダルを表示する
2. ユーザーがアラートモーダルを閉じたとき、CookingAppは同日の再表示を防ぐためにlocalStorageにフラグを保存する
3. ユーザーがアラート内のクイック料理登録ボタンをクリックしたとき、CookingAppはCOOKEDエントリを作成し、アラートを即座に非表示にする
4. アラートが表示されるとき、CookingAppは警告メッセージと励ましメッセージの間でランダムに選択する
5. ユーザーが3日以内に料理をしたとき、CookingAppはアラートを表示しない

### Requirement 8: 買い物リスト管理機能

**User Story:** ユーザーとして、レシピから食材を買い物リストに追加し、購入状況を管理したい。そうすることで、買い物を効率化できる。

#### Acceptance Criteria

1. ユーザーがレシピから食材を買い物リストに追加したとき、CookingAppは買い物リストアイテムを作成する
2. ユーザーが既存のアイテムと同じ正規化された名前と単位を持つ食材を追加したとき、CookingAppは数量を合算する
3. ユーザーが同じ名前だが異なる単位を持つ既存のアイテムに食材を追加したとき、CookingAppは別のアイテムを作成する
4. ユーザーがアイテムをチェック済みとしてマークしたとき、CookingAppはIsCheckedをtrueに設定し、IsCheckedAtタイムスタンプを記録する
5. IsCheckedAtから3日が経過したとき、CookingAppはチェック済みアイテムを自動的に削除する

### Requirement 9: 多言語対応機能

**User Story:** ユーザーとして、日本語または韓国語でアプリケーションを利用したい。そうすることで、母国語で快適に操作できる。

#### Acceptance Criteria

1. ユーザーがプロフィール設定で優先言語を選択したとき、CookingAppはPreferredLanguage属性に設定を保存する
2. ユーザーが言語設定なしでアプリケーションにアクセスしたとき、CookingAppはブラウザの言語設定をデフォルトとして使用する
3. システムがUI要素を表示するとき、CookingAppはユーザーの優先言語でテキストをレンダリングする
4. システムがエラーメッセージまたはバリデーションメッセージを返すとき、CookingAppはAccept-Languageヘッダーに基づいてユーザーの優先言語でメッセージを提供する
5. ユーザー生成コンテンツが存在する場合、CookingAppはユーザーが入力した元の言語でコンテンツを表示する

### Requirement 10: 管理者機能

**User Story:** 管理者として、ユーザーとレシピを管理したい。そうすることで、システムの品質と安全性を維持できる。

#### Acceptance Criteria

1. 管理者が管理ダッシュボードにアクセスしたとき、CookingAppはすべてのユーザーの統計を表示する
2. 管理者がユーザーアカウントを選択したとき、CookingAppはアカウントの停止または削除を許可する
3. 管理者がレシピを閲覧したとき、CookingAppは審査待ちを含むすべてのレシピを表示する
4. 管理者がレシピを不適切としてマークしたとき、CookingAppはレシピを非公開ステータスに設定する
5. 管理者がレシピを削除したとき、CookingAppは参照を保持しながらレシピを削除済みとしてマークする

### Requirement 11: セキュリティとセッション管理

**User Story:** ユーザーとして、安全にアプリケーションを利用したい。そうすることで、個人情報が保護される。

#### Acceptance Criteria

1. ユーザーがパスワードを作成したとき、CookingAppはパスワードが少なくとも8文字で、大文字、小文字、数字、特殊文字（$ * . [ ] { } ( ) ? - " ! @ # % & / \ , > < ' : ; | _ ~ ` + =）を含むことを検証する
2. クライアントとサーバー間でデータが送信されるとき、CookingAppはTLS 1.2以上のHTTPSを使用する
3. ユーザーが複数のデバイスからログインしたとき、CookingAppは同時セッションを許可する
4. リフレッシュトークンが期限切れになったとき、CookingAppはユーザーをログイン画面にリダイレクトする
5. 認証が必要なとき、CookingAppはID管理にAWS Cognitoを使用する

### Requirement 12: パフォーマンス要件

**User Story:** ユーザーとして、アプリケーションが迅速に応答することを期待する。そうすることで、ストレスなく操作できる。

#### Acceptance Criteria

1. ユーザーが一般的なリクエストを行ったとき、CookingAppはリクエストの90%を2秒以内に完了する
2. ユーザーがログインまたはレシピ検索を実行したとき、CookingAppはリクエストの90%を1秒以内に完了する
3. システムが同時ユーザーを処理するとき、CookingAppは少なくとも10の同時接続をサポートする
4. エラーが発生したとき、CookingAppはINFOレベル以上でCloudWatchにイベントをログ記録する
5. APIエラーが発生したとき、CookingAppはユーザーフレンドリーなエラーメッセージを表示する
