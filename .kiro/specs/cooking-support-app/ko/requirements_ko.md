# 요구사항 문서

## 소개

본 애플리케이션은 1인 가구 또는 2~4인 가족을 대상으로 한 자취 지원 및 식비 절약 웹 애플리케이션입니다. Uber Eats 등의 배달 서비스 의존에서 벗어나도록 지원하고, 간단한 레시피 제공을 통해 요리에 대한 심리적 장벽을 낮추며, 식재료의 유통기한과 보관 방법을 제시하여 계획적인 장보기를 촉진하고 음식물 쓰레기를 줄입니다.

주요 기능으로 레시피 검색·편집, 일정 관리(실적 기록), 장보기 목록, 알림 표시를 제공합니다. 백엔드는 Java (Spring Boot)와 Clean Architecture, 프론트엔드는 TypeScript (React, React Router, Redux), 인프라는 AWS 서버리스 구성을 채택합니다.

## 용어집

- **CookingApp**: 자취 지원 및 식비 절약 애플리케이션 시스템 전체
- **User**: 애플리케이션을 이용하는 등록 사용자
- **Recipe**: 요리의 제목, 식재료, 조리 순서, 이미지를 포함하는 레시피 정보
- **Schedule**: 사용자의 요리 예정 또는 실적 기록
- **PLANNED**: 일정 유형으로, 요리 예정을 나타냄
- **COOKED**: 일정 유형으로, 요리 실적을 나타냄
- **ShoppingList**: 사용자의 장보기 목록
- **Review**: 레시피에 대한 별점 평가와 댓글
- **AIAdvisor**: 식재료에 대한 보관 방법이나 대체 식재료를 제시하는 AI 기능
- **Alert**: 요리 실적이 없는 기간이 계속될 때의 경고 표시
- **Administrator**: 시스템 관리자
- **Cognito**: AWS Cognito에 의한 인증 서비스
- **S3**: Amazon S3 스토리지 서비스
- **DynamoDB**: Amazon DynamoDB 데이터베이스 서비스

## 요구사항

### Requirement 1: 사용자 등록 및 인증

**User Story:** 사용자로서, 계정을 생성하고 로그인하여 자신의 프로필을 관리하고 싶다. 그렇게 함으로써 개인에 맞춘 요리 기록과 장보기 목록을 저장할 수 있다.

#### Acceptance Criteria

1. 사용자가 유효한 이메일 주소와 패스워드 요건을 충족하는 패스워드를 제공했을 때, CookingApp은 Cognito를 사용하여 새 계정을 생성한다
2. 사용자가 유효한 인증 정보를 제공했을 때, CookingApp은 사용자를 인증하고 시스템 접근을 허용한다
3. 액세스 토큰이 1시간 후, 또는 리프레시 토큰이 90일 후에 만료되었을 때, CookingApp은 재인증을 요구한다
4. 사용자가 프로필 이미지를 업로드했을 때, CookingApp은 파일 크기가 5MB 이하이고 형식이 JPEG 또는 PNG임을 검증한다
5. 사용자가 계정 삭제를 요청했을 때, CookingApp은 계정과 프로필 이미지를 즉시 삭제하고 게시한 레시피와 리뷰를 익명화한다

### Requirement 2: 레시피 검색 및 조회

**User Story:** 사용자로서, 카테고리, 식재료, 조리 시간으로 레시피를 검색하고 상세 정보를 조회하고 싶다. 그렇게 함으로써 자신에게 맞는 요리를 찾을 수 있다.

#### Acceptance Criteria

1. 사용자가 카테고리, 식재료, 또는 조리 시간을 포함하는 검색 조건을 지정했을 때, CookingApp은 일치하는 레시피를 반환한다
2. 사용자가 레시피를 선택했을 때, CookingApp은 레시피의 제목, 수량과 단위를 포함하는 식재료, 조리 순서, 이미지를 표시한다
3. 사용자가 레시피 상세 정보를 조회했을 때, CookingApp은 표시 가능 상태의 모든 리뷰를 표시한다
4. 사용자가 삭제된 레시피를 조회했을 때, CookingApp은 레시피가 삭제되었음을 나타내는 메시지를 표시한다
5. 레시피에 식재료가 존재하는 경우, CookingApp은 각 식재료를 이름, 수량, 단위, 선택적 메모, 선택적 플래그와 함께 표시한다

### Requirement 3: 레시피 등록 및 편집

**User Story:** 사용자로서, 자신의 레시피를 등록·편집하고 싶다. 그렇게 함으로써 오리지널 레시피를 공유하고 나중에 참조할 수 있다.

#### Acceptance Criteria

1. 사용자가 레시피의 제목, 식재료, 조리 순서, 선택적 이미지를 제공했을 때, CookingApp은 새 레시피를 생성한다
2. 사용자가 식재료 정보를 제공했을 때, CookingApp은 이름이 1~50자, 수량이 0~9999 범위, 단위가 사전 정의 목록에서 선택되었음을 검증한다
3. 사용자가 자신의 레시피를 편집했을 때, CookingApp은 레시피 정보를 업데이트한다
4. 사용자가 자신의 레시피를 삭제했을 때, CookingApp은 일정과 장보기 목록의 참조를 유지하면서 레시피를 삭제됨으로 표시한다
5. 사용자가 레시피 이미지를 업로드했을 때, CookingApp은 이미지를 S3에 저장하고 파일 크기가 5MB 이하이고 형식이 JPEG 또는 PNG임을 검증한다

### Requirement 4: AI 어드바이저 기능

**User Story:** 사용자로서, 선택한 식재료에 대한 보관 방법이나 대체 식재료 제안을 받고 싶다. 그렇게 함으로써 식재료를 낭비 없이 활용할 수 있다.

#### Acceptance Criteria

1. 사용자가 식재료를 선택하고 AI 조언을 요청했을 때, CookingApp은 Gemini API를 호출하고 보관 방법과 대체 식재료를 반환한다
2. AI API 호출이 실패하고 24시간 이내의 캐시가 존재할 때, CookingApp은 캐시된 응답을 표시한다
3. AI API 호출이 실패하고 캐시가 존재하지 않을 때, CookingApp은 재시도 버튼과 정적 힌트를 표시한다
4. AI API의 속도 제한에 도달했을 때, CookingApp은 배너 메시지를 표시하고 30초 후에 자동으로 재시도한다
5. AI API의 속도 제한에 도달했을 때, CookingApp은 수동 재시도 버튼을 제공한다

### Requirement 5: 레시피 평가 기능

**User Story:** 사용자로서, 레시피에 별점 평가와 댓글을 게시하고 다른 사용자의 평가를 조회하고 싶다. 그렇게 함으로써 레시피의 품질을 판단할 수 있다.

#### Acceptance Criteria

1. 사용자가 1~5의 별점 평가와 최대 300자의 선택적 댓글을 제공했을 때, CookingApp은 레시피의 리뷰를 생성한다
2. 사용자가 자신의 리뷰를 조회했을 때, CookingApp은 편집과 삭제를 허용한다
3. 사용자가 리뷰를 신고했을 때, CookingApp은 신고 카운트를 증가시킨다
4. 리뷰가 3건 이상의 신고를 받았을 때, CookingApp은 자동으로 상태를 숨김으로 설정한다
5. 사용자가 리뷰를 조회했을 때, CookingApp은 표시 가능 상태의 리뷰만 표시한다

### Requirement 6: 일정 관리 기능

**User Story:** 사용자로서, 요리의 예정과 실적을 캘린더로 관리하고 싶다. 그렇게 함으로써 요리 습관을 시각화하고 지속할 수 있다.

#### Acceptance Criteria

1. 사용자가 캘린더를 조회했을 때, CookingApp은 선택된 월 또는 주의 예정과 실적 항목을 표시한다
2. 사용자가 날짜에 대해 요리 활동을 등록했을 때, CookingApp은 COOKED 일정 항목을 생성하고 LastCookingDate를 업데이트한다
3. 사용자가 미래 날짜에 대해 요리 예정을 등록했을 때, CookingApp은 PLANNED 일정 항목을 생성한다
4. 사용자가 PLANNED 항목을 COOKED로 변환했을 때, CookingApp은 일정 유형을 COOKED로 업데이트한다
5. 사용자가 과거 일정 항목의 편집 또는 삭제를 요청했을 때, CookingApp은 변경을 허용한다

### Requirement 7: 게으름 방지 알림 기능

**User Story:** 사용자로서, 요리를 하지 않은 기간이 계속되면 경고를 받고 싶다. 그렇게 함으로써 자취 습관을 유지할 수 있다.

#### Acceptance Criteria

1. 사용자가 대시보드에 접근하고 LastCookingDate로부터 3일이 경과하여 4일째 0시가 되었을 때, CookingApp은 알림 모달을 표시한다
2. 사용자가 알림 모달을 닫았을 때, CookingApp은 당일 재표시를 방지하기 위해 localStorage에 플래그를 저장한다
3. 사용자가 알림 내의 빠른 요리 등록 버튼을 클릭했을 때, CookingApp은 COOKED 항목을 생성하고 알림을 즉시 숨긴다
4. 알림이 표시될 때, CookingApp은 경고 메시지와 격려 메시지 사이에서 무작위로 선택한다
5. 사용자가 3일 이내에 요리를 했을 때, CookingApp은 알림을 표시하지 않는다

### Requirement 8: 장보기 목록 관리 기능

**User Story:** 사용자로서, 레시피에서 식재료를 장보기 목록에 추가하고 구매 상황을 관리하고 싶다. 그렇게 함으로써 장보기를 효율화할 수 있다.

#### Acceptance Criteria

1. 사용자가 레시피에서 식재료를 장보기 목록에 추가했을 때, CookingApp은 장보기 목록 항목을 생성한다
2. 사용자가 기존 항목과 동일한 정규화된 이름과 단위를 가진 식재료를 추가했을 때, CookingApp은 수량을 합산한다
3. 사용자가 동일한 이름이지만 다른 단위를 가진 기존 항목에 식재료를 추가했을 때, CookingApp은 별도의 항목을 생성한다
4. 사용자가 항목을 체크됨으로 표시했을 때, CookingApp은 IsChecked를 true로 설정하고 IsCheckedAt 타임스탬프를 기록한다
5. IsCheckedAt로부터 3일이 경과했을 때, CookingApp은 체크된 항목을 자동으로 삭제한다

### Requirement 9: 다국어 지원 기능

**User Story:** 사용자로서, 일본어 또는 한국어로 애플리케이션을 이용하고 싶다. 그렇게 함으로써 모국어로 편안하게 조작할 수 있다.

#### Acceptance Criteria

1. 사용자가 프로필 설정에서 우선 언어를 선택했을 때, CookingApp은 PreferredLanguage 속성에 설정을 저장한다
2. 사용자가 언어 설정 없이 애플리케이션에 접근했을 때, CookingApp은 브라우저의 언어 설정을 기본값으로 사용한다
3. 시스템이 UI 요소를 표시할 때, CookingApp은 사용자의 우선 언어로 텍스트를 렌더링한다
4. 시스템이 오류 메시지 또는 검증 메시지를 반환할 때, CookingApp은 Accept-Language 헤더에 기반하여 사용자의 우선 언어로 메시지를 제공한다
5. 사용자 생성 콘텐츠가 존재하는 경우, CookingApp은 사용자가 입력한 원래 언어로 콘텐츠를 표시한다

### Requirement 10: 관리자 기능

**User Story:** 관리자로서, 사용자와 레시피를 관리하고 싶다. 그렇게 함으로써 시스템의 품질과 안전성을 유지할 수 있다.

#### Acceptance Criteria

1. 관리자가 관리 대시보드에 접근했을 때, CookingApp은 모든 사용자의 통계를 표시한다
2. 관리자가 사용자 계정을 선택했을 때, CookingApp은 계정의 정지 또는 삭제를 허용한다
3. 관리자가 레시피를 조회했을 때, CookingApp은 심사 대기 중인 것을 포함한 모든 레시피를 표시한다
4. 관리자가 레시피를 부적절함으로 표시했을 때, CookingApp은 레시피를 비공개 상태로 설정한다
5. 관리자가 레시피를 삭제했을 때, CookingApp은 참조를 유지하면서 레시피를 삭제됨으로 표시한다

### Requirement 11: 보안 및 세션 관리

**User Story:** 사용자로서, 안전하게 애플리케이션을 이용하고 싶다. 그렇게 함으로써 개인정보가 보호된다.

#### Acceptance Criteria

1. 사용자가 패스워드를 생성했을 때, CookingApp은 패스워드가 최소 8자이고 대문자, 소문자, 숫자를 포함하는지 검증한다
2. 클라이언트와 서버 간에 데이터가 전송될 때, CookingApp은 TLS 1.2 이상의 HTTPS를 사용한다
3. 사용자가 여러 기기에서 로그인했을 때, CookingApp은 동시 세션을 허용한다
4. 리프레시 토큰이 만료되었을 때, CookingApp은 사용자를 로그인 화면으로 리디렉션한다
5. 인증이 필요할 때, CookingApp은 ID 관리에 AWS Cognito를 사용한다

### Requirement 12: 성능 요구사항

**User Story:** 사용자로서, 애플리케이션이 신속하게 응답하기를 기대한다. 그렇게 함으로써 스트레스 없이 조작할 수 있다.

#### Acceptance Criteria

1. 사용자가 일반적인 요청을 했을 때, CookingApp은 요청의 90%를 2초 이내에 완료한다
2. 사용자가 로그인 또는 레시피 검색을 실행했을 때, CookingApp은 요청의 90%를 1초 이내에 완료한다
3. 시스템이 동시 사용자를 처리할 때, CookingApp은 최소 10개의 동시 연결을 지원한다
4. 오류가 발생했을 때, CookingApp은 INFO 레벨 이상으로 CloudWatch에 이벤트를 로그 기록한다
5. API 오류가 발생했을 때, CookingApp은 사용자 친화적인 오류 메시지를 표시한다
